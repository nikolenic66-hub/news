# Football News Bot

Автоматический Telegram-автопубликатор футбольных новостей на Python. Проект независим от футбольного менеджера и должен использовать отдельный проект Neon.

## Что реализовано

- RSS-сбор футбольных новостей, фильтр свежести и дедупликация по URL/похожим заголовкам.
- DeepSeek-редактор с редакционными правилами, JSON-ответом, очисткой длинных тире и шаблонных фраз.
- Дневной лимит DeepSeek-запросов и консервативный бюджет расходов с учётом токенов.
- Поиск реальных фотографий в Wikimedia Commons, фильтрация лицензий, подпись автора и лицензии.
- Защита от повторной публикации при неопределённом результате Telegram API.
- Лимит до 10 постов в сутки, интервал между публикациями и временное окно.
- PostgreSQL/Neon, версионированные миграции Alembic, сохранённая очередь и история.
- Перекрывающийся запуск блокируется через PostgreSQL advisory lock.
- Режим однократного запуска для расписания, чтобы не держать worker запущенным круглосуточно.
- В production-образ не устанавливаются тестовые зависимости.

## Безопасные режимы

APP_MODE по умолчанию равен collect_only. В этом режиме бот только собирает RSS-кандидатов в базу. Он **не вызывает DeepSeek, не ищет фотографии и не публикует посты**.

- collect_only: сбор RSS для проверки источников и базы.
- prepare: обработка DeepSeek и поиск лицензированных фотографий; публикация в Telegram выключена.
- live: полная автоматическая публикация в канал. Включать только после тестов.

Не переключайте APP_MODE=live, пока не выполнена проверка на тестовом канале.

## Переменные окружения

Скопируйте значения из .env.example в переменные Amvera. Не добавляйте реальные ключи в репозиторий.

- DATABASE_URL: строка подключения отдельного проекта Neon.
- APP_MODE: начните с collect_only, затем используйте prepare, и только потом live.
- DEEPSEEK_API_KEY: требуется для режимов prepare и live.
- TELEGRAM_BOT_TOKEN и TELEGRAM_CHANNEL_ID: требуются только для live.
- MAX_DEEPSEEK_CALLS_PER_DAY=30 и DEEPSEEK_DAILY_BUDGET_USD=0.08: пределы приложения для контроля расходов.
- MAX_POSTS_PER_DAY=10: программный верхний предел публикаций.

Расчёт расходов использует консервативные цены DeepSeek по тарифу peak, настроенные через переменные окружения. Это дополнительная защита приложения, а не замена биллинговых ограничений/контроля баланса в аккаунте провайдера.

## База Neon и миграции

Миграции выполняются при старте командой alembic upgrade head. Не используйте строку подключения менеджера, не добавляйте таблицы новостного проекта в его базу. Миграции хранятся в migrations/versions.

## Локальная разработка

1. Python 3.12+.
2. python -m venv .venv
3. Установите зависимости: pip install -r requirements-dev.txt
4. Заполните локальный .env по примеру .env.example.
5. Запустите проверки: python -m pytest -q
6. Посмотрите текущие миграции: python -m alembic heads
7. Перед запуском с реальными переменными используйте python -m app.main --check. Он проверит конфигурацию, миграции, соединение с БД и RSS, не обращаясь к DeepSeek, Wikimedia и Telegram.

Для реального запуска нужен доступ к отдельной PostgreSQL/Neon базе. В collect_only Telegram и DeepSeek ключи не нужны.

## Amvera

В репозитории есть Dockerfile. Выберите отдельный проект Amvera. При обычном запуске приложение работает циклом и опрашивает источники с интервалом POLL_INTERVAL_MINUTES.

Если Cron Jobs в вашем аккаунте позволяет запускать этот же код с его переменными окружения и тарифицирует только время выполнения, используйте команду python -m app.main --once по расписанию вместо круглосуточного worker. Перед выбором проверьте условия тарификации в панели Amvera. Этот режим закрывает подключения после цикла и защищает от двух одновременно работающих экземпляров через advisory lock.

## Важные ограничения

- Команда python -m app.main --check выполняет preflight без AI/photo/Telegram-вызовов.
- 10 постов в сутки — максимум, а не обещание публиковать 10 материалов при отсутствии достойных новостей.
- Модель использует только факты из RSS-фрагмента. Если сведений недостаточно, материал отбрасывается.
- Фотография из Wikimedia может быть иллюстративной; такие публикации помечаются. Если изображение без подходящей лицензии не найдено, пост пропускается.
- Автоматический распознаватель лицензии не является юридической гарантией: нужно соблюдать условия конкретной лицензии и проверять коммерческие права для изображённого события/персоны.
- До live-режима нужно протестировать доступность RSS, DeepSeek, подбор фотографий, правильность атрибуции, Telegram-публикацию и поведение при сбое.
